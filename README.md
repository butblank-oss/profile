# 인지장애 B2G 시장·경쟁사 분석

조달청 나라장터 계약원장에서 추출한 인지·치매 관련 계약 112건과, 내부 전략 덱·공개
자료를 근거로 만든 시장 분석·경쟁사 리서치 문서입니다. 정적 사이트로 서비스합니다.

## 페이지

| 경로 | 내용 |
|---|---|
| `index.html` | 목차 · 데이터 출처 3층 구조 |
| `competitor-profiles.html` | 경쟁사 17곳 프로파일 + 계약원장 명단 (주력 문서) |
| `market-analysis.html` | 수요 모수 → TAM/SAM → 조달 실집행 + 포지셔닝 맵 2종 |
| `comparison.html` | 경쟁사 17곳 비교표 — 컬럼 선택 · 정렬 · 갱신 |
| `contract-analysis-deck.html` | 16:9 발표 슬라이드 14장 (참고용 초기 산출물) |
| `data/contracts_raw.csv` | 나라장터 계약원장 112건 원본 (2024.01–2026.08) |
| `screenshots/*.webp` | 경쟁사 앱 화면 38장 (`<image-slot src>` 로 연결) |

## 리서치 워크스페이스

`competitor-profiles.html` 은 읽기용 문서가 아니라 **계속 채워 나가는 도구**입니다.

- **스크린샷** — 슬롯에 이미지를 끌어다 놓거나 클릭해서 선택. 섹션당 10칸이고 빈 칸은
  항상 1개만 보입니다. 채우면 다음 칸이 열립니다. 드래그로 순서를 바꾸고, 클릭하면
  라이트박스(`←` `→` 이동, `Esc` 닫기)가 열립니다.
- **입력칸 · 소감칸** — 타이핑하는 즉시 저장됩니다. 값이 들어가면 테두리가 점선에서
  실선으로 바뀝니다.

### 저장 위치

입력값과 이미지는 **보고 있는 브라우저에만** 저장됩니다. 서버로 올라가지 않습니다.

| 데이터 | 저장소 | 키 |
|---|---|---|
| 스크린샷 이미지·리프레임 | IndexedDB `dementia-research` / `image-slots` | `.image-slots.<0-23>.state.json` |
| 추가 확인 항목 입력값 | localStorage | `cp-spec-v1` |
| 직접 사용 소감 | localStorage | `cp-notes-v1` |
| 스크린샷 순서 | localStorage | `cp-shot-order-v1` |

따라서 **다른 기기·다른 브라우저에서는 보이지 않고**, 브라우저 사이트 데이터를 지우면
함께 사라집니다. 시크릿 모드에서는 저장이 막혀 화면 우하단에 경고 배너가 뜹니다.
여러 사람이 함께 채워야 한다면 서버 API + 오브젝트 스토리지로 옮겨야 합니다.

이미지는 저장 전에 캔버스로 리샘플됩니다 — 긴 변 1800px, WebP 품질 0.92.

## 비교표 (`comparison.html`)

17곳을 10개 컬럼으로 한 표에 놓고 봅니다. **표를 따로 저장해 두지 않습니다** —
`테이블 갱신하기` 를 누를 때마다 `competitor-profiles.html` 을 다시 fetch 해서 파싱하고,
그 위에 브라우저에 저장된 수정분을 덮어 씁니다. 그래서 프로파일에 값을 입력하면
갱신 한 번으로 반영됩니다. 같은 오리진이라 가능한 구조입니다.

| 컬럼 | 어디서 읽나 |
|---|---|
| 서비스명 | 섹션 `h2` + 서비스명 줄 |
| 판매채널 | 칸 배지 |
| 과금형태 · 나라장터 계약 | 인덱스 표의 해당 행 |
| 게임 구성 · 수 / 앱 다운로드수 / 스토어 평점 / 최근 업데이트 / 기관용 관리·리포트 | 각 프로파일 입력칸 |
| 사용소감 정리 | 소감 원문에서 앞 3항목 추출 |

### 화면 전환 — 비교표 / 채널 포지셔닝

상단 탭으로 두 화면을 오갑니다. 보던 화면은 `cmp-view-v1` 에 남습니다.

`채널 포지셔닝` 은 **시장 분석 문서의 04 섹션을 그때그때 읽어 온 것**입니다.
복사해 두지 않습니다 — 복사본은 원본이 바뀌면 어긋납니다. 표가
`competitor-profiles.html` 을 읽는 것과 같은 방식입니다.

섹션은 순서가 아니라 **제목 글자**(`채널 포지셔닝`)로 찾습니다. 시장 분석에서
섹션 순서가 바뀌어도 따라갑니다. 가져온 뒤 섹션의 배경·여백과 안쪽 컨테이너의
`max-width` 를 벗겨 이 페이지 폭에 맞춥니다.

맵 화면에서는 표 전용 도구(채울 목록·내보내기·한 장에 보기)를 숨깁니다. 맵에는
채울 칸도 정렬도 없습니다. `테이블 갱신하기` 는 보고 있는 화면을 다시 읽습니다.

### 한 장에 보기 · 업체 고르기

`볼 업체` 칩으로 비교할 곳만 고릅니다. 칸 이름(지자체 예산 4 · 경로 다름 2 …)을
누르면 그 채널만 한 번에 잡힙니다. 선택은 `cmp-rows-v1` 에 남습니다.

`한 장에 보기` 는 표를 화면 한 장에 밀어 넣습니다.

1. 머리말·설명을 접습니다. 이게 화면의 3분의 2를 먹고 있어서, 접지 않으면 아무리
   줄여도 들어가지 않습니다.
2. 글자·여백을 줄이고 긴 칸은 두 줄로 자릅니다. 자르는 것은 `td` 가 아니라 **안쪽
   div** 입니다 — `td` 의 `display` 를 바꾸면 테이블 셀이 아니게 되어 폭·높이
   계산이 통째로 깨집니다(축소율이 4% 로 나왔던 원인).
3. 그래도 넘치면 `transform: scale()` 로 비율 축소합니다. 45% 밑으로 내려가야 하면
   맞추기를 포기하고 무엇을 줄여야 하는지 알려 줍니다.

안내 문구는 **가로·세로 중 어느 쪽이 걸렸는지** 보고 달라집니다. 세로가 걸렸으면
컬럼을 아무리 꺼도 커지지 않습니다 — 표 높이는 업체 수만 따르기 때문입니다.
17곳 전체는 52%, 칸 하나(4곳 안팎)는 축소 없이 들어갑니다.

한 장 모드에서는 셀 클릭 입력을 끕니다. 칸 크기가 계속 바뀌면 입력이 어렵습니다.

### 페이지에서 직접 채우기

비교표에서 바로 입력할 수 있습니다. 세 가지 방법이 같은 곳에 저장됩니다.

| | 쓰는 법 |
|---|---|
| 표 안에서 | 옅은 색 칸을 누르면 그 자리가 입력칸이 됩니다 |
| 채울 목록 | `채울 목록 열기` — 비어 있는 칸만 업체별로 모아서 보여 줍니다 |
| 프로파일에서 | 기존처럼 각 프로파일의 입력칸·소감란 |

저장 위치는 프로파일 페이지와 **같은 localStorage 키**입니다 (`cp-spec-v1`,
`cp-notes-v1`). 키 규칙도 같습니다 — 섹션 안 등장 순서로 `sid:N`. 다른 저장소를
쓰면 두 화면이 어긋나므로 반드시 같은 키를 씁니다.

`채울 목록` 의 남은 칸 수는 **입력칸이 실제로 있는데 비어 있는 것**만 셉니다.
섹션마다 입력칸 구성이 달라서, 없는 칸까지 세면 숫자가 영영 줄지 않습니다.

### 채운 값을 저장소에 넣기

입력은 그 브라우저에만 남습니다. 다른 기기에서도 보이게 하려면 값을 밖으로
꺼내야 합니다.

1. 비교표에서 `채운 값 내보내기` → `comparison-edits.json`
2. 그 파일의 값을 `competitor-profiles.html` 의 해당 `input value` / `textarea`
   에 넣고 커밋

내보내기는 **HTML 기본값과 달라진 것만** 담습니다. 파일에는 저장 키(`silvia:7`)와
업체명·라벨이 같이 들어 있어 어디에 넣을지 찾을 수 있습니다.

### 입력칸은 라벨로 찾습니다

입력칸 구성이 섹션마다 다릅니다 — 12곳은 표준 6종이고, 기억하리·하야트·치매체크·
스마케어·뉴로네이션은 각자 다른 항목을 씁니다. 그래서 위치(`sid:N`)가 아니라 **라벨**로
찾고, 같은 뜻을 다르게 적은 것들(`앱 설치 수` / `앱 다운로드 수`)은 후보를 여러 개 둡니다.

`게임 구성 · 수` 는 이 저장소에서 13곳에 새로 추가했습니다. 나머지 4곳에는 이미
`콘텐츠 종류·수` 가 있어서 그걸 같은 컬럼으로 읽습니다.

⚠️ **입력칸을 추가할 때는 반드시 그리드 맨 끝에 붙이십시오.** 저장 키가 섹션 안
등장 순서(`sid:N`)라, 중간에 끼우면 뒤 항목들의 키가 밀려 저장된 값이 엉뚱한 칸으로
갑니다.

### 자동요약은 추출입니다

소감 원문의 앞 3항목(불릿이면 불릿, 아니면 문장)을 **그대로** 뽑습니다. 다시 쓴 문장이
아닙니다 — 정적 사이트라 런타임에 AI 를 부를 수 없기도 하고, 조사 내용이 요약 과정에서
달라지면 안 되기 때문입니다. 전문은 셀의 `전문 보기` 로 펼칩니다.

### 정렬

`10만` · `1억 2,676만` 같은 한국어 수 표기를 숫자로 바꿔 비교합니다. 문자 정렬이면
`10만` 이 `4.0` 보다 뒤로 가기 때문입니다. 빈 값은 정렬 방향과 무관하게 항상 아래로
내려갑니다.

선택한 컬럼은 localStorage `cmp-cols-v1` 에 남습니다.

## 채워진 리서치 데이터

프로토타입에서 조사해 둔 내용이 이미 들어가 있습니다. 어디에 어떻게 들어갔는지가
수정할 때 중요합니다.

| 데이터 | 어디에 | 양 |
|---|---|---|
| 스크린샷 | `screenshots/*.webp` + `<image-slot src="./screenshots/…">` | 38장 |
| 직접 사용 소감 | `<textarea data-note>` 안에 직접 | 9개 섹션 |
| 추가 확인 항목 | `<input data-spec value="…">` | 34개 |
| 스크린샷 순서 | `data/research-seed.js` → localStorage `cp-shot-order-v1` | 3개 섹션 |

스크린샷·소감·입력값은 **HTML 에 박아** 뒀습니다. 저장소를 받은 누구나, 브라우저
저장소가 막힌 환경에서도 똑같이 봅니다. 드래그로 바꾼 순서만 HTML 에 표현할 자리가
없어서 시드(localStorage)로 넣었습니다.

### 저장값이 HTML 기본값을 이깁니다

프로토타입 원본은 저장된 값을 `el.value === ''` 일 때만 되살렸습니다. HTML 에 값이
박힌 상태에서는 사용자가 고쳐도 새로고침 때 원래 값으로 돌아갑니다 — 핸드오프 문서가
경고한 "새로고침하면 사라지는" 버그입니다. 이 저장소에서는 조건을 바꿨습니다.

```js
// 원본
if (store[key] != null && el.value === '') el.value = store[key];
// 여기
if (store[key] != null) el.value = store[key];
```

빈 브라우저에서는 HTML 기본값이 그대로 보이고, 한 번 고치면 그 값이 남습니다.
고친 내용은 그 브라우저에만 있습니다 — 저장소에 반영하려면 HTML 을 직접 고쳐
커밋해야 합니다.

### 이미지를 바꾸거나 지우면

사용자가 슬롯에 새 이미지를 넣으면 IndexedDB 에 저장되고 `src` 보다 우선합니다.
지우면 `src` 의 원본으로 되돌아갑니다 — 저장소가 준 기본값은 남고 개인 변경만
얹히는 구조입니다.

## 칸(채널) 구분

경쟁사는 **누가 돈을 내는가**로 묶습니다. 핸드오프 원본의 다섯 칸에 `경로 다름` 하나를
더했습니다.

| 칸 | 배지 색 | 뜻 |
|---|---|---|
| 지자체 예산 | `#8944ab` / `#f4ecfa` | 지자체·보건소 예산으로 산다 |
| 경로 다름 | `#1d7a3e` / `#e9f6ec` | **제품 형태는 우리와 닮았으나 판매 경로가 다르다** |
| 개인 B2C | `#0a7e8c` / `#e6f4f5` | 개인이 직접 쓴다 (무료·유료) |
| 돌봄기관 | `#b25000` / `#fdf1e9` | 주간보호·복지관 등 기관이 산다 |
| 병 · 의원 | `#0071e3` / `#e8f1fd` | 처방·보험으로 돈이 나온다 |
| 명단만 | `#6e6e73` / `#f0f0f2` | 프로파일 없이 계약원장 명단에만 |

`경로 다름`(실비아·데카르트)은 이 저장소에서 추가한 칸입니다. 두 곳은 제품 구성이 우리와
가장 가깝지만 파는 경로가 민간보험·다채널이라, 채널 기준으로만 묶으면 뒤로 밀려 실제
경쟁 강도가 드러나지 않았습니다. 대비는 4.83:1 로 기존 칸들(4.12~5.24) 범위 안에 맞췄고,
초록은 기존 다섯 색과 겹치지 않는 유일한 색상군이라 골랐습니다.

## 수치를 인용하기 전에

문서에 실린 수치는 확실성이 세 층으로 갈립니다. 출처 표기를 떼고 인용하지 마십시오.

- **수요 모수** (치매 100만 · MCI 300만) — 로완 공동대표 GISC 2025 발표. 발표자 주장이며
  미검증이고, 1,140만의 20%가 300만이 아니라는 계산 오류를 포함합니다.
- **TAM 16.2조 / SAM 24.6억** — TAM은 건보공단 통계연보 실집행(공식 통계),
  SAM은 256곳 × 960만 **가정치**입니다.
- **계약 7.68억 · 46곳 · 중간값 794만** — 나라장터 계약원장 기준으로 검증됨. 다만 금액은
  용역 43건, 건수는 112건 기준이라 모수가 다릅니다.

국가 치매관리비용 22조 9,000억은 의도적으로 제외했습니다. 환자 수 × 1인당 사회적 비용
추정치이며 정부 집행 예산이 아니어서, 조달 시장과 나란히 놓으면 수치가 왜곡됩니다.

2026년은 8월까지만 집계되어 연간 비교에 쓸 수 없습니다.

## 공개 범위

내부 전략 자료입니다. 모든 페이지에 `noindex, nofollow` 가 붙어 있고 `robots.txt` 는
전체를 `Disallow` 합니다. GitHub Pages 로 서비스하면 **URL을 아는 사람은 누구나 볼 수
있습니다** — 검색에 안 걸릴 뿐 비공개가 아닙니다. 접근 제한이 필요하면 비공개 저장소 +
인증이 붙는 호스팅으로 옮기십시오.

## 로컬 실행

빌드가 없습니다. 정적 파일을 그대로 서빙하면 됩니다.

```
python3 -m http.server 8000
```

`file://` 로 직접 열어도 대부분 동작하지만, IndexedDB 오리진이 달라져 저장이 기기별로
갈립니다. HTTP 로 여십시오.
